# mini-task-manager

A tiny command-line to-do list. The app itself is deliberately trivial —
the point of this project is to show **how a C++ project is laid out
across multiple files**.

## Folder structure

```
mini-task-manager/
├── include/              # Header files (.h) — declarations: "what exists"
│   ├── task.h
│   └── task_manager.h
├── src/                  # Source files (.cpp) — definitions: "how it works"
│   ├── main.cpp          # Entry point: the menu loop, int main()
│   ├── task.cpp          # Implements the Task class
│   └── task_manager.cpp  # Implements the TaskManager class
├── build/                # Generated by the build (not committed)
├── Makefile              # Build script for `make`
├── CMakeLists.txt        # Build script for CMake (the common industry choice)
├── .gitignore            # Tells git to ignore build/
└── README.md
```

## Why split code this way?

| File type | Contains | Example |
|-----------|----------|---------|
| `.h` header | Class declarations, function signatures | `bool completeTask(int id);` |
| `.cpp` source | The actual function bodies | `bool TaskManager::completeTask(int id) { ... }` |

- Other files `#include` a **header** to learn what a class looks like,
  without needing to see its implementation.
- Each header has an **include guard** (`#ifndef TASK_H ... #endif`) so it
  is only processed once, even if included from several places.
- Each class gets its own `.h` / `.cpp` pair with matching names.
- `main.cpp` stays small: it only wires the pieces together.

### Who includes whom

```
main.cpp ─────────► task_manager.h ───► task.h
task_manager.cpp ─► task_manager.h
task.cpp ─────────► task.h
```

## How building works

Building a multi-file C++ project happens in two steps:

1. **Compile** — each `.cpp` file is compiled on its own into an object file:
   `src/task.cpp → build/task.o`
   The `-Iinclude` flag tells the compiler where to find the headers.
2. **Link** — all the `.o` files are combined into one executable:
   `main.o + task.o + task_manager.o → build/mini-task-manager`

That's why changing only `task.cpp` only needs `task.o` recompiled.

## Build and run

**With make** (on Windows with MSYS2/MinGW use `mingw32-make`):

```
make
./build/mini-task-manager
make clean
```

OR 

```
mingw32-make
.\build\mini-task-manager.exe
make clean
```

**With CMake:**

```
cmake -S . -B build
cmake --build build
./build/mini-task-manager
```

**By hand** (one command, no build tool):

```
g++ -std=c++17 -Iinclude src/*.cpp -o mini-task-manager
```
